## 2. Objetivo da Task
Criar o service puro que gera mensagem e URL de conversa para confirmacao/cancelamento usando dados do agendamento e profissional unico.

---

## 3. Descrição Detalhada
- Criar `src/features/whatsapp/whatsappService.ts` como funcao pura, sem integracao paga ou envio automatico.
- A mensagem deve incluir nome do cliente, data, horario e profissional.
- Rejeitar payload incompleto com erro tipado.
- Garantir encoding de URL quando houver telefone/whatsapp disponivel.
- Nao criar dependencia externa para provedor de mensagem.

## 7. Notas / Observações
- `gates: [qa]` porque e service puro simples, sem side-effect externo.
- **Desvio de path do teste (registrado, não pedido de aprovação)**: o teste foi
  criado em `src/features/whatsapp/whatsappService.test.ts`, não em
  `tests/unit/whatsappService.test.ts` como listado em §5.1. Motivo: este repo
  não tem diretório `tests/unit/` — todo teste unitário existente (T1/T2:
  `auth.test.ts`, `firestorePaths.test.ts`, `errors.test.ts`, `time.test.ts`,
  `validators.test.ts`) é colocado junto do módulo em `src/`, e
  `vitest.config.mts` só inclui `{app,src}/**/*.test.{ts,tsx}` — um arquivo em
  `tests/unit/` nunca seria coletado por `npm test`. Colocar o teste no path
  literal do card o deixaria morto (nunca executado). Mantida a convenção real
  do projeto; CT-07/CT-08 cobertos e verdes (8 testes no arquivo, incluindo
  negative companions extras para cliente/data/telefone ausentes).
